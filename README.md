# Customer Service Campaign

Customer Service Campaign is an ASP.NET Core Web API application created as a recruitment project.

The application simulates a campaign where agents reward loyal customers with discounts.

Each agent can reward a maximum of 5 customers per day.

After the campaign, a CSV file with customers who successfully completed a purchase can be imported. The application updates the campaign data and provides campaign results through the API.

## Technologies

The project uses:

- C#
- .NET 8
- ASP.NET Core Web API
- Entity Framework Core
- SQLite
- SOAP Web Service
- Swagger / OpenAPI
- xUnit
- Moq
- Entity Framework Core InMemory

## Main Features

### Customer Validation

Before a reward is created, the application checks if the customer exists.

Customer data is retrieved from the external FindPerson SOAP service.

The SOAP service is accessed through `PersonService`.

### Reward Assignment

Agents can assign rewards to customers through the API.

The main business rule is:

- One agent can reward a maximum of 5 customers per day.

When a reward is created:

- `CustomerId` identifies the customer.
- `AgentId` identifies the agent.
- `RewardDate` is generated by the server.
- `PurchaseSuccessful` is initially set to `false`.

If an agent already has 5 rewards for the current day, the API returns `400 Bad Request`.

### CSV Import

After the campaign, a CSV file can be imported with customers who successfully completed a purchase.

Expected CSV format:

```text
CustomerId
1
2
3
```

The application checks:

- if a file was provided;
- if the file has a `.csv` extension;
- if the first row contains the `CustomerId` header;
- if every CustomerId is a positive integer.

For matching customers, the application changes:

```text
PurchaseSuccessful = true
```

### Campaign Results

Campaign results are available through the API.

The result contains:

- total number of rewards;
- number of successful purchases;
- number of unsuccessful purchases.

## API Endpoints

| Method | Endpoint | Description |
| --- | --- | --- |
| GET | `/api/Person/{id}` | Finds a customer using the SOAP service |
| POST | `/api/Campaign/rewards` | Assigns a reward to a customer |
| POST | `/api/Campaign/import` | Imports successful purchases from a CSV file |
| GET | `/api/Campaign/results` | Returns campaign results |

## Security

The API is protected with an API key.

The API key is sent in the HTTP header:

```text
X-API-Key
```

Swagger contains an **Authorize** option where the API key can be entered before testing the endpoints.

The API key is not stored directly in the source code.

For local development, it can be configured using .NET User Secrets.

Example:

```json
{
  "ApiKey": "your-api-key"
}
```

Requests without an API key or with an incorrect API key return `401 Unauthorized`.

## Database

The application uses SQLite as the database and Entity Framework Core for database access.

The main model is `CampaignReward`.

It contains:

- `Id`
- `CustomerId`
- `AgentId`
- `RewardDate`
- `PurchaseSuccessful`

Entity Framework Core migrations are used to create the database structure.

## SOAP Integration

The application uses an external FindPerson SOAP service to check customer data.

`PersonService` communicates with the SOAP service.

`IPersonService` is used as an interface between the controller and `PersonService`.

This also makes testing easier because the real SOAP service does not need to be called during automated tests.

## Automated Tests

Automated tests are implemented using:

- xUnit
- Moq
- Entity Framework Core InMemory

The tests check:

- that a new reward has `PurchaseSuccessful = false`;
- that an agent with 5 rewards cannot create a sixth reward on the same day;
- that an agent with less than 5 rewards can successfully create a reward.

The tests use an InMemory database, so the real SQLite database is not changed.

Moq is used to simulate `IPersonService`, so the tests do not depend on the external SOAP service.

The tests follow the Arrange-Act-Assert pattern:

- **Arrange** - prepare the test data;
- **Act** - execute the functionality;
- **Assert** - check the result.

## Application Flow

The main application flow is:

```text
Client / Swagger
       |
       v
ASP.NET Core API
       |
       +----> CampaignController
       |          |
       |          +----> Entity Framework Core ----> SQLite
       |
       +----> PersonController
                  |
                  +----> IPersonService
                            |
                            +----> PersonService
                                      |
                                      +----> FindPerson SOAP Service
```

Dependency Injection is used to provide services and the database context to the controllers.

## How to Run the Project

1. Clone the repository.
2. Open `CustomerServiceCampaign.sln` in Visual Studio.
3. Restore the NuGet packages.
4. Configure the API key using .NET User Secrets.
5. Run `CustomerServiceCampaign.Api`.
6. Open Swagger.
7. Click **Authorize** and enter the API key.
8. Test the API endpoints.

## How to Run the Tests

Open **Test Explorer** in Visual Studio.

Click **Run All Tests**.

The automated tests are located in:

```text
CustomerServiceCampaign.Tests
```
